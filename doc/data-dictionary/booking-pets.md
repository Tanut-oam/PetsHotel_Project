# Data Dictionary: booking_pets

ตาราง `booking_pets` เชื่อมการจองกับสัตว์เลี้ยงใน PetsHotel โดยหนึ่งแถวหมายถึงสัตว์เลี้ยงหนึ่งตัวที่เข้าพักในการจองหนึ่งรายการ

ตารางนี้รองรับความสัมพันธ์ Many-to-Many ระหว่าง `bookings` และ `pets` และมีรหัสของตนเองเพื่อให้รายงานการดูแลและบริการเสริมอ้างถึงสัตว์ในการเข้าพักครั้งนั้นได้

| คอลัมน์ | ชนิดข้อมูล PostgreSQL | NULL ได้ | คีย์ / ข้อกำหนด | ความหมาย |
|---|---|---|---|---|
| `id` | BIGINT | ไม่ได้ | Primary Key, สร้างค่าแบบ IDENTITY | รหัสรายการสัตว์เลี้ยงในการจอง |
| `booking_id` | BIGINT | ไม่ได้ | Foreign Key → `bookings.id` | การจองที่สัตว์เลี้ยงเข้าพัก |
| `pet_id` | BIGINT | ไม่ได้ | Foreign Key → `pets.id` | สัตว์เลี้ยงที่เข้าพักในการจองนั้น |

## ความสัมพันธ์

- การจองหนึ่งรายการมีรายการสัตว์เลี้ยงได้หลายรายการ: `booking_pets.booking_id` → `bookings.id`
- สัตว์เลี้ยงหนึ่งตัวมีประวัติการเข้าพักหลายครั้งได้: `booking_pets.pet_id` → `pets.id`
- รายการสัตว์เลี้ยงในการจองหนึ่งรายการมีรายงานการดูแลได้หลายวัน: `daily_care_reports.booking_pet_id` → `booking_pets.id`
- รายการสัตว์เลี้ยงในการจองหนึ่งรายการรับบริการเสริมได้หลายรายการ: `booking_extra_services.booking_pet_id` → `booking_pets.id`
- ใน Entity ความสัมพันธ์ `booking` และ `pet` เป็น `ManyToOne` และโหลดข้อมูลแบบ `LAZY`
- `Booking.bookingPets` เป็น `OneToMany` โดยกำหนด `cascade = ALL` และ `orphanRemoval = true`
- วันที่เข้าพักและสถานะเก็บในตาราง `bookings` ส่วนชื่อ ประเภท และเจ้าของสัตว์เก็บในตาราง `pets` ไม่ได้เก็บซ้ำใน `booking_pets`

## กฎการทำงานที่เกี่ยวข้อง

### การเพิ่มสัตว์ในการจอง

- การสร้างการจองต้องเลือกสัตว์เลี้ยงอย่างน้อยหนึ่งตัว
- รหัสสัตว์ในคำขอ `petIds` ต้องไม่เป็น `NULL` และต้องไม่ซ้ำกัน
- สัตว์ทุกตัวต้องมีอยู่ในระบบ ยังใช้งานอยู่ และเป็นของผู้จอง
- จำนวนสัตว์ต้องไม่เกินความจุห้องที่เลือก
- `BookingServiceImpl.prepareBooking()` เรียก `Booking.addPet(pet)` สำหรับสัตว์แต่ละตัว
- `Booking.addPet()` สร้าง `BookingPet` โดยกำหนดทั้ง `booking` และ `pet` แล้วเพิ่มลงใน `Booking.bookingPets`
- เมื่อบันทึก Booking รายการ BookingPet ถูกบันทึกผ่าน cascade ของ JPA
- Entity ไม่ได้ประกาศ Unique constraint สำหรับคู่ `booking_id` กับ `pet_id` การป้องกันสัตว์ซ้ำในการจองปัจจุบันตรวจในคำขอที่ Service

### การตรวจสัตว์ที่มีการจองซ้อน

- `BookingPetRepository.findOverlappingPetIds()` ค้นรหัสสัตว์ที่มีการจองทับช่วงวันที่ที่ต้องการ
- การสร้างการจองนับเฉพาะสถานะ `PENDING`, `CONFIRMED` และ `CHECKED_IN` เป็นสถานะที่ยังสงวนสัตว์เลี้ยง
- เงื่อนไขช่วงวันที่ซ้อนกันคือ `existing.checkInDate < requested.checkOutDate` และ `existing.checkOutDate > requested.checkInDate`
- ช่วงเข้าพักนับรวมวันเช็กอิน แต่ไม่รวมวันเช็กเอาต์ การจองใหม่ที่เริ่มในวันเช็กเอาต์ของการจองเดิมจึงไม่ถือว่าซ้อนกัน
- หากพบสัตว์ที่จองซ้อน ระบบปฏิเสธการสร้างการจองด้วย `PetNotAvailableException`
- `BookingServiceImpl.getPetAvailability()` ใช้ข้อมูลนี้แจ้งหน้าฟอร์มให้ปิดตัวเลือกสัตว์ที่ติดจองในช่วงวันที่เลือก
- การป้องกันการจองซ้อนตรวจในโค้ด ไม่ได้ประกาศเป็น constraint ของตาราง `booking_pets`

### รายงานการดูแลและบริการเสริม

- รายงานการดูแลอ้างถึง `booking_pets.id` เพื่อระบุทั้งสัตว์และการเข้าพักครั้งที่เกี่ยวข้อง
- ตาราง `daily_care_reports` มี Unique constraint สำหรับคู่ `booking_pet_id` กับ `report_date` เพื่อไม่ให้มีรายงานซ้ำของสัตว์ในการเข้าพักเดียวกันในวันเดียวกัน
- บริการเสริมอ้างถึง `booking_pets.id` เพื่อระบุว่าสัตว์ตัวไหนในการจองเป็นผู้รับบริการ
- `BookingServiceImpl` สร้าง `bookingPetsByPetId` เพื่อจับคู่รหัสสัตว์กับ BookingPet แล้วนำไปผูกกับรายการบริการเสริม
- ผู้รับบริการต้องเป็นสัตว์ในการจองนั้น และไม่สามารถเลือกสัตว์ตัวเดิมซ้ำสำหรับบริการเดียวกันในคำขอได้

### การเก็บประวัติ

- สัตว์ตัวเดิมสามารถมี BookingPet คนละรายการสำหรับการเข้าพักคนละครั้งได้
- การยกเลิกการจองเปลี่ยนสถานะใน Booking โดยไม่ลบ BookingPet
- เมื่อการจองเป็น `CANCELLED` หรือ `CHECKED_OUT` รายการสัตว์ยังอยู่เป็นประวัติ แต่ไม่นับเป็นรายการที่สงวนสัตว์ในการตรวจช่วงวันที่ซ้อน
- Repository มีเมธอด `deleteByBookingId()` แต่เส้นทางยกเลิกการจองปัจจุบันไม่ได้เรียกเมธอดนี้

## ตัวอย่างข้อมูล

สมมติว่าการจองรหัส 101 มีสัตว์เลี้ยงรหัส 3 และ 4 ส่วนสัตว์รหัส 3 กลับมาเข้าพักอีกครั้งในการจองรหัส 102 โดยช่วงวันที่ไม่ซ้อนกัน

| `id` | `booking_id` | `pet_id` |
|---|---|---|
| 201 | 101 | 3 |
| 202 | 101 | 4 |
| 203 | 102 | 3 |

- รหัส 201 และ 203 อ้างถึงสัตว์ตัวเดียวกัน แต่เป็นการเข้าพักคนละครั้ง
- รายงานการดูแลของสัตว์รหัส 3 ในการจอง 101 ต้องอ้าง `booking_pet_id = 201`
- บริการเสริมของสัตว์รหัส 3 ในการจอง 102 ต้องอ้าง `booking_pet_id = 203`
- รหัสในตัวอย่างเป็นข้อมูลสมมติ ไม่ใช่ค่าเริ่มต้นของฐานข้อมูล

## เมธอด Repository ที่เกี่ยวข้อง

| เมธอด | หน้าที่ |
|---|---|
| `findByBookingId(bookingId)` | ค้นรายการสัตว์ทั้งหมดในการจองที่ระบุ |
| `deleteByBookingId(bookingId)` | ลบรายการสัตว์ของการจองที่ระบุ |
| `findOverlappingPetIds(...)` | ค้นรหัสสัตว์ที่ติดจองในช่วงวันที่และสถานะที่ระบุ |
| `findReportableBookingPets(statuses)` | ค้นรายการสัตว์ในการจองตามสถานะที่ผู้เรียกกำหนด พร้อมโหลดข้อมูลการจอง ผู้จอง และสัตว์ |
